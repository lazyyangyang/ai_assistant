# AI Career 响应式改造方案

日期：2026-10-27。状态：设计稿，尚未实现或通过设备测试。

建议在现有 React 前端上实施移动优先的响应式改造，让桌面、平板和手机浏览器使用同一套路由、业务 Hook 和后端接口。重点是让核心操作在小屏上完整可达，并处理软键盘、触摸、语音和长内容。这里的 PC 客户端按桌面浏览器理解；本期不包含原生 App、桌面安装包、离线使用或 PWA 安装能力。

配套文档：[功能模块调整设计](02-module-design.md)、[测试设计与验收](03-test-design.md)。

## 断点和布局规则

断点依据可用宽度，不能用 User Agent 决定业务行为。以下数值是本项目的设计选择，实施时与 Tailwind 配置保持一致。

| 宽度 | 布局 |
| --- | --- |
| 320–639 px | 单列；紧凑顶栏；业务详情用全宽面板；聊天侧栏改抽屉 |
| 640–767 px | 宽单列；首页可多列；仍使用会话抽屉 |
| 768–1023 px | 顶栏横向导航；管理卡片可两列；聊天仍用抽屉，给输入和消息留空间 |
| ≥1024 px | 常驻约 240 px 会话侧栏；业务内容采用内嵌面板；主内容最大宽度建议 1200 px |

通用页左右间距为小屏 16 px、大屏 24 px。手机聊天可缩减外边距至 8 px；长文本使用 `min-width: 0` 和适当断行。正文与输入文字建议 16 px，辅助说明 12–14 px。不得通过全局 `overflow-x: hidden` 掩盖溢出，不禁用双指缩放。

导航使用顶栏加移动菜单，首期不增加底部导航，避免与键盘、输入区争夺空间。菜单中保留首页、JD、简历、面试、账号和主题入口；登录后的长用户名截断显示，同时允许查看全名。

## 聊天视口和滚动方案

普通页面沿文档滚动；JD、简历和面试采用独立聊天工作区。工作区内部使用三行布局：上下文摘要、可收缩消息区、自然高度输入区。消息区承担主滚动，业务详情在覆盖面板内独立滚动，不再在聊天前铺满全部业务卡片。

优先以 `100dvh` 管理动态高度，`100svh` 作为基础值；顶栏实际高度通过布局或 ResizeObserver 获得，去掉统一减 `8rem` 的估算。设置安全区内边距并评估 `viewport-fit=cover`。顶部与底部安全区不能重复计入。

软键盘可能只缩小 visual viewport，不能假定 `dvh` 在所有目标设备上都避开键盘。真机出现遮挡时，由单一 `useChatViewport` Hook 订阅 VisualViewport 的 resize/scroll，按可见区域和顶栏实际位置设置聊天可用高度；仅作用于聊天路由，清理监听，并在页面缩放时避免强制覆盖用户缩放。[MDN VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)

抽屉宽度不超过视口，包含明确关闭按钮。打开时限制背景交互与滚动，关闭后恢复；不得关闭聊天 Hook 或重建 SSE。改变宽度时关闭不再适用的浮层并释放滚动锁。

## 数据和接口边界

布局调整默认不需要新接口、数据库迁移或模型提示词变化。组件复用既有 Hook → `api.ts` → `http.ts` → FastAPI 路由及认证依赖 → 数据库 → 响应更新链路。

Access Token 仍仅在内存；Refresh Cookie、CSRF 请求头、允许 Origin、401 最多刷新重试一次、Web Locks 和 BroadcastChannel 协调保持不变。不为旧浏览器添加认证降级实现。

手机联调使用受信任 HTTPS 且前后端同源 `/api` 的测试地址，配置允许 Origin 和 Secure Cookie。手机上的 localhost 指手机本身；通过电脑局域网 HTTP 地址访问不作为语音及认证浏览器能力的验收环境。不得在文档或测试记录中保存真实密钥、简历或 Token。

同一账号在另一设备可以重新请求已有服务端简历和聊天数据，但本地 JD 复用数据、未发送草稿和浏览器主题不会因此同步。本期在 JD 保存处标注“仅保存在此浏览器”。云端 JD 管理应作为单独需求，设计归属校验、接口、数据模型和迁移后再实施。
