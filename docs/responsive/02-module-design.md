# AI Career 响应式功能模块调整设计

日期：2026-10-27。状态：待实现。本文落实[响应式方案](01-responsive-plan.md)中的组件边界、页面交互和状态规则；验收编号见[测试设计](03-test-design.md)。

## 手机聊天结构

```text
┌─────────────────────────┐
│ AI Career        菜单   │
├─────────────────────────┤
│ 历史会话  当前模块  资料 │
│ 当前简历或 JD 摘要       │
├─────────────────────────┤
│                         │
│      可滚动消息区       │
│      返回最新消息       │
│                         │
├─────────────────────────┤
│ 多行输入框              │
│ 录音  播放  更多   发送  │
└─────────────────────────┘
```

生成时发送位置切换为停止，保持稳定可达。结束面试放在辅助工具栏或“更多”中，始终有文字入口；点击后显示确认，再执行已有结束请求。输入行不与所有业务操作争抢同一行宽度。键盘展开时优先保留消息、输入、发送，压缩摘要而非隐藏核心操作。

## 导航和账号

移动菜单同时提供业务导航、主题、登录注册或账号退出。用户名使用省略显示，菜单详情展示全文。切换路由关闭菜单；关闭后恢复触发按钮焦点。导航使用链接语义，动作使用按钮语义，避免链接内嵌按钮。登录和注册表单保持单列；加入正确 label、自动填充语义与可聚焦错误提示，键盘开启时提交可达。

菜单或面板采用对话框语义时，必须有可访问名称、Escape 关闭、焦点限制、背景不可交互和关闭后焦点恢复。无需模态的普通导航展开区使用 `aria-expanded` 与 `aria-controls`，不强加焦点陷阱。

## JD 解析

手机默认展示聊天与“查看解析结果”按钮，生成结构化结果后提示已更新但不强制弹窗；用户打开后按摘要、技能、职责、硬性条件阅读。保存按钮位于面板操作区，明确“保存供本浏览器复用”。桌面可以展开内嵌结果，仍允许收起。

继续由 `useJDPage` 接收结构化事件并调用 `jdStorage`。关闭结果面板不清空结果；切换会话时只呈现该会话结果，没有结果时显示空态，不能继续展示前一会话数据。结果为空或未完成时维持现有保存有效性判断。

## 简历管理和诊断

手机顶部显示“当前简历名称与版本”和“管理简历”。管理面板包含上传、版本列表和预览三个区段，使用面板主滚动，避免列表与预览同时成为两个小型滚动窗口。桌面可采用列表和预览双列。

上传保留 PDF、TXT、DOCX，调用系统文件选择器；取消选择不触发上传。长文件名换行，标题输入和上传按钮有独立标签。上传中禁用重复提交；失败后保留可重试信息。关闭面板不卸载正在上传的业务状态。

选中版本与“设为当前”分开表达：选中是当前页面上下文；设为当前调用已有服务端更新。删除前确认名称和版本，成功后刷新并选择有效版本；失败不乐观移除。删除操作位置与选中行分离，减少触摸误点。

诊断回复保存仍保存最近 AI 回复全文，不承诺生成排版简历。保存按钮标记“将最近回复保存为新版本”，生成进行中不可保存半截内容。这要求从聊天向页面传递生成状态；按钮文案和守卫必须一起修改。

调用链保持：`ResumePage` → `useResumePage` → `apiUploadResume/apiUpdateResume/apiDeleteResume/apiCreateResumeVersion` → Axios → `routers/resumes.py` 与认证依赖 → 数据库 → 刷新列表。响应式改造不改变接口字段和归属检查。

## 会话和流式聊天

新建和历史入口对全部宽度开放。会话列表需要加载、空、失败重试三种状态；切换后高亮当前项并关闭手机抽屉。历史请求以 request ID 或取消令牌隔离，旧会话迟到响应不能覆盖新会话。

生成中或录音处理中禁用新建、切换会话和更改简历上下文，并解释需先停止或等待完成。停止操作不得显示普通请求失败。切换已有会话前如有未发送文字，提示保留当前或丢弃后切换；首期不新增本地持久化草稿。

消息区在用户靠近底部时跟随流式输出；用户向上阅读后停止自动拉回，出现“返回最新消息”按钮。宽度变化或抽屉关闭后重测虚拟列表高度，以消息 ID 和相对偏移保持阅读位置。测试覆盖中文 SSE 分块和 Markdown 高度随流增长。

移动触摸输入默认 Enter 换行、点击发送；桌面物理键盘保留 Enter 发送、Shift+Enter 换行。不能只用屏幕宽度判断键盘类型，提供明确的“Enter 发送”选项，触摸环境默认关闭。任何模式下 `isComposing` 或输入法组合期间均不发送；发送事件统一检查空文本、busy 和已结束状态。

## 模拟面试和语音

面试上下文收起为当前简历摘要，开始前可打开调整。结束动作需确认；处理中禁用重复点击，成功后沿用 `/interview/end/:sessionId`。报告失败时保留会话入口，不自动重复调用模型。

语音统一采用点击开始、点击停止，替换必须按住的交互，使触屏、鼠标和键盘有相同路径。用户可以一直使用文字输入。

| 状态 | 可执行操作 | 退出与异常处理 |
| --- | --- | --- |
| idle | 开始录音或编辑文字 | 检查 getUserMedia 与 MediaRecorder 能力 |
| requesting | 取消权限等待 | 使请求序号失效；权限稍后成功也立即释放流，不开始录音 |
| recording | 停止并转写，或取消丢弃 | 展示计时和状态；取消、离开页面、隐藏页面或音轨终止时停止并释放，不自动转写 |
| transcribing | 等待或取消请求 | 忽略过期结果；取消不覆盖文字，不误报普通失败 |
| error | 重试或改用文字 | 释放全部媒体轨道，恢复可操作状态 |

回填转写时比较开始时草稿版本；如果用户已编辑，提供插入或替换选择，不能静默覆盖。应用层建议录音上限 60 秒，达到后停止并转写；该数值是本期产品约束，需要实测与后端限制共同确认。

用 `MediaRecorder.isTypeSupported()` 探测候选，加入 MP4 候选并以实际 `recorder.mimeType` 或录制数据 MIME 构建 Blob，不伪造编码。上传文件名按实际 MIME 映射到 `.mp4`、`.webm`、`.ogg` 等；未知格式明确报错或按实际浏览器格式验证后支持。后端非 WAV 经 FFmpeg 转 WAV 的路径需用真实录音文件验证。[MDN 类型探测](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static)、[MDN MIME 属性](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/mimeType)

TTS 自动播放失败后保留手动播放按钮，显示“点击播放”；区分生成中、可播放、播放中和失败。切换会话或离开页面时停止播放并释放 Object URL。暂停、重播属于本期播放控件调整，不能仅依赖浏览器自动播放成功。

## 报告和通用反馈

手机标题、返回、总分与摘要纵向排列，评分项与改进建议按单列阅读。宽屏恢复并列。空报告、加载失败、结构化解析失败分别显示；解析失败保留原文。当前报告 Hook 通过会话列表取反馈，本期沿用，但要补齐请求失败的显式提示及重试入口。

报告长词断行，优先级标签不被挤出屏幕。图标按钮均有可访问名称；加载状态通过简短状态提示播报，不逐字播报 SSE；错误不能只依赖自动消失的 Toast。暗色模式与减少动画偏好纳入验证。
