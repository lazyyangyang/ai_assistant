# 聊天附件测试与验收方案

日期：2026-10-30。状态：测试设计，以下用例均未执行。关联：[设计](chat-attachments-design.md)、[待办](chat-attachments-tasks.md)。

## 1. 分层与数据

- 后端单元：状态转换、限额、预算、校验、解析路由；使用临时目录与独立测试 SQLite。
- 后端集成：实际 HTTP 二进制上传、数据库约束、真实磁盘合并、解析器和独立 Worker，故障注入可恢复。
- 前端 Vitest：状态、队列、取消、身份切换、SSE 与发送门槛。
- 浏览器 E2E：复用现有 Playwright 基础设施；真实上传端点和 Worker，模型可用桩替代，但不能据此声称模型联调通过。
- 提供方联调：第二阶段真实图片/文本模型，使用无敏感合成样本；单列调用次数、费用与模型版本。运行前明确环境与调用范围。

建立无个人信息 fixtures：中文/emoji/中英混合 TXT、带 BOM 与非法字节文本；MD；包含段落/表格/页眉/文本框/图片的 DOCX；文字/扫描/混合/空白页/旋转/加密/损坏 PDF；旧 DOC；PNG/JPEG/WebP；伪后缀文件。大文件用可重复种子生成，并预存独立工具计算的整文件哈希。文件必须包含首部、中间、末尾标记，解析结果逐项比对，不能只验证返回 200。

边界数据：0、1 字节；分片大小减一/等于/加一；单文件上限减一/等于/加一；5/6 个附件；消息总大小和用户配额边界；页数/像素/解压量/提取字符数上限。资源攻击样本在限制环境生成，不对开发机发起无上限解压或内存消耗。

## 2. 验收矩阵

| 编号 | 场景与操作 | 必须满足的断言 |
|---|---|---|
| T01 类型与限额 | 测全部支持类型、伪 MIME/后缀、空文件、大小/数量边界；绕过前端直接调用接口；多请求争抢最后配额 | 能力与实际一致，服务器独立拒绝；并发不超配额；错误包含原因且无内部路径 |
| T02 数据兼容 | 迁移含旧用户/聊天/简历的复制库；新增附件关联；尝试重复请求 ID、重复分片 | 旧数据不丢失；唯一约束有效；重复请求不重复预留/入库；外键与所属用户正确 |
| T03 完整性 | 乱序片、丢片、重复片、篡改片、错误总哈希、末片短/长、并发 complete、complete 响应丢失 | 缺片明确索引；哈希不符不可就绪；服务器确认字节不重复累加；完成文件与独立参考逐字节一致；仅一个完整化任务 |
| T04 传输恢复 | 每个阶段断网；刷新后重选相同/不同文件；暂停/取消；429/503；上传句柄过期；取消与片完成竞争 | 只补缺片；错误文件拒绝续传；有限退避；取消无错误 toast 且不能复活；过期 410；旧分片最终回收 |
| T05 崩溃恢复 | Worker 合并中、重命名后提交前、解析中、结果提交前强制结束；重启；租约过期后旧 Worker 返回 | 任务可恢复；无永久 processing；旧 generation 不覆盖新结果；无损坏文件标成功；孤儿可对账回收 |
| T06 解析覆盖 | 真实解析 fixtures，逐页/段比对；页眉/表格/文本框/图片；编码异常；超过页/字符上限；OCR 缺页 | 预期文本与顺序正确；不支持内容有警告；失败页定位；无静默 errors=ignore 或截断；partial 不自动发送；页数不是识别准确率 |
| T07 聊天闭环 | 仅附件、文字+多附件、多轮追问、重新打开历史；超预算；partial 确认旧版本；SSE 中断与重复提交；JD/面试报告 | 服务器持久关联且只关联本轮；历史上下文来自数据库；范围/来源可追溯；超预算显式处理；过期确认拒绝；请求幂等；既有 structured/done 保持兼容 |
| T08 账号隔离 | A 上传时退出并登录 B；A 请求迟到；双标签不同账号；猜测 A 的 ID 下载/预览/完成/重试/关联；同账号多标签 | B 不出现 A 文件与回调；所有越权 404；不广播凭证/内容；同账号合法恢复；401 最多刷新重试一次；存储不可用不破坏页内能力 |
| T09 文件安全与存储 | 路径穿越文件名、HTML/Markdown 脚本、提示注入、DOCX 膨胀、超像素、磁盘满、解析器超时 | 原名不决定路径；预览不执行脚本；附件不成为系统指令；限额生效、错误可解释；无无限进程/空间增长；不泄露内容和密钥 |
| T10 交互与可访问性 | 选择/拖拽/粘贴；多文件一部分失败；窄屏；键盘；中文输入法；录音；上传 100% 后慢校验 | 进度标签真实；未就绪不能误发；移除不误删历史；失败可恢复；不遮挡发送按钮；语音/输入法行为不回归；未部署格式有明确原因 |
| T11 性能与竞争 | 同机上传/合并/OCR 与聊天并发；SQLite 写竞争；5 个用户×2 文件；磁盘水位；长期运行 | 无完整性错误/死锁；内存有界且接近设计预算；任务队列可排空；超时可回收；延迟与资源指标记录并达到下节门槛 |
| T12 清理与回滚 | dry-run 与执行对比；清理并发绑定/Worker 完成；用户删除聊天；关闭开关；失败部署回滚 | dry-run 不改文件/数据；关联原件不被误删；预留正确释放；关闭开关后历史可看；旧应用兼容策略经过验证；不迁移真实用户库 |
| T13 第二阶段真实能力 | DOC 转换、OCR、视觉模型、长文档检索/分段摘要；文档末尾埋关键问题；缺一个摘要分段 | 模型实际接收到目标输入；回答可追踪来源；遗漏分段明确失败/partial；检索不宣称全文阅读；实际提供方支持经验证 |

## 3. 性能测量与初始通过门槛

先记录 OS、CPU、RAM、磁盘剩余/类型、浏览器、Python/Node、解析器与模型版本，以及本地/限速网络条件。测试文件和并发固定，至少三次重复；不得把设计阈值描述为当前实测能力。

1. 上传 100 MiB 合成文件，4 MiB 分片；测前端哈希内存、后端上传内存、合并峰值与耗时。上传进程内存增量不得随完整文件大小线性增长；初拟单上传增量不超过 64 MiB，浏览器哈希 Worker 不超过 64 MiB，超出则分析并修订实现或明确限额。
2. 5 用户各 2 文件并发上传，Worker 并发 1；所有文件最终哈希一致。对不调用真实 AI 的聊天鉴权/历史接口测 p95，相比同机空载增幅初拟不超过 30%，且 p95 小于 1 秒；失败应限制上传并发或拆分资源后复测。
3. 逐个测试 10/100/500 页文档；记录完成时间和解析峰值。120 秒或 OCR 600 秒超时必须明确终止并释放资源；超时不算成功，但应能重试/解释。
4. 租约失效后应在“租约期限+两次轮询周期”内重新领取；取消后在一个心跳周期内停止任务，文件清理允许异步但必须有可观测结果。
5. 低速网络加随机断连，最终合并哈希一致；暂停后不继续发送新分片，重试只补缺片。重复任务不重复计费调用模型。

## 4. 执行命令与证据

实施后从 frontend 执行 `pnpm run build`、`pnpm exec vitest run`，改动文件执行 `pnpm exec eslint <files>`；E2E 使用项目 Playwright 配置执行附件专项。从 backend 使用 `.\.venv\Scripts\python.exe -m pytest` 执行附件专项及聊天/认证/简历回归。具体测试文件名随实现确定。

真实联调仅启动本任务需要且可追踪归属的服务；测试数据库、上传根目录与端口必须隔离，不能用真实 .env 数据库或真实简历做破坏性测试。迁移测试只针对临时库。终止任务仅终止本任务进程。

证据目录拟用 `docs/verification/chat-attachments-YYYY-MM-DD/`：环境说明、命令与退出码、失败清单、状态截图、哈希对照、资源曲线、真实模型联调说明。日志脱敏，不包含文件内容/凭证。每项标为通过/失败/未运行/阻塞，禁止用 Mock 通过替代真实验收。

## 5. 发布门槛

- 第一阶段：T01—T12 对已启用能力全部通过；越权、字节缺失、静默丢内容、误删、身份串页属于阻断缺陷。
- 第二阶段：DOC、图片、OCR、长文档功能逐项启用前通过相应用例及 T13；未启用能力如实显示不支持，不能宣称完整需求已交付。
- 必须实际演示：断网续传、篡改片拒绝、扫描页提示、超上下文处理、账号切换隔离、重启恢复和历史附件回显。
