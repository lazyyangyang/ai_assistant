# AI Career 标签页独立登录测试执行流程

日期：2026-10-27。状态：测试计划，全部用例待执行。对应 [实施任务清单](tab-session-isolation-tasks.md)、[模块详细设计](tab-session-isolation-module-design.md) 和 [总方案](tab-session-isolation-design.md)。

先验证单模块的状态和协议，再使用真实后端完成同浏览器多页验证，最后验证浏览器生命周期及真机行为。Mock 结果、真实后端结果和真实模型结果分别记录。本轮仅编写任务与测试流程，没有运行下述测试。

## 1 测试层次与环境

| 层次 | 实际运行对象 | 主要证明 | 不替代的范围 |
| --- | --- | --- | --- |
| L0 静态检查 | TypeScript 构建、ESLint | 类型、依赖和代码规范 | 运行时身份与 Cookie |
| L1 单元和组件 | Vitest、Testing Library、可控 Promise 与时钟 | 队列、重试、迟到响应、状态保留 | 浏览器 Cookie 和 BFCache |
| L2 后端集成 | pytest、真实临时 SQLite、ASGI 请求 | 签名/会话校验、事务与数据归属 | 浏览器 Cookie 携带与界面 |
| L3 浏览器集成 | 真实前端和 FastAPI、同 context 多 page | 标签页身份、Cookie 路径、真实业务读写与广播 | 真机、真实模型质量 |
| L4 人工生命周期 | 桌面原生操作及手机真实浏览器 | 复制/恢复、BFCache、录音和后台切换 | 未测试设备行为 |

L3 认证、/me、简历读写均使用真实后端与测试数据库。模型生成、STT/TTS 外部服务在后端服务边界替换为确定性夹具，保留实际路由和鉴权。专门的故障注入用例可拦截响应，但必须标明拦截范围，不能用它证明真实 Cookie 或服务端授权。

真实模型与外部语音服务联调不在默认自动化内；如执行，应单独记录配置、结果和成本授权范围。通过本计划只能声明相应认证、状态及协议范围通过，不能据此声明真实 AI 服务已联调。

## 2 测试数据和隔离

页面统一叫 P1、P2，账号统一叫 U_A、U_B，避免“标签页 A”和“账号 A”混淆。测试凭证为运行时生成的非真实账号，日志不保存密码、完整 Token、Cookie 或认证头。

| 数据 | 准备内容 | 用途 |
| --- | --- | --- |
| U_A、U_B | 每轮唯一账号 | 不同账号归属验证 |
| SID_A1、SID_A2、SID_B1 | 由真实登录响应获取，不能预填假 sid | 同账号多会话与不同账号 |
| R_A1、R_A2、R_B1 | 有明显测试标记的无敏感简历 | 列表、选择、删除与越权 |
| JD_A | 固定完整结构化结果 | 会话内存缓存隔离 |
| 文件 | 合法 TXT/PDF/DOCX、损坏文件、空文件 | 写成功、失败与解析回归 |
| SSE | 中文跨 UTF-8 块、structured、done、断流 | 流消费和取消 |
| 音频 | 已知有效时长、格式可识别的夹具 | STT/TTS 回归，不复用已知过短夹具作为成功输入 |

后端 pytest 当前在导入 app 前设置独立临时 DATABASE_URL，使用 create_all/drop_all；这只证明模型建表，迁移另由迁移测试验证。E2E 服务是另一个进程，不会自动继承 pytest 的隔离配置，必须由专门启动器显式提供数据库 URL 并确认实际连接目标。

E2E 每轮使用唯一数据库与端口。初始化前记录并校验解析后的绝对路径属于本轮测试目录；禁止对日常 ai_career.db 执行 drop_all、清会话或迁移。应用配置不覆盖本地 .env，环境变量通过测试子进程传入。测试服务不得复用无法确认归属的已运行服务。

同一用例内两个页面必须共用同一 browser context、同源和存储分区；用例之间新建 context 或使用唯一账号隔离。不得预加载用户 storageState 或注入 Token 绕过登录；reload 后也不能用测试脚本偷偷恢复凭证。

## 3 阶段执行流程

### G0 基线检查

1. 读取 AGENTS.md，记录 Git 状态、版本/未提交改动摘要、依赖与测试配置。
2. 确认测试数据库和模型替换边界，检查服务启动器不会连接真实 AI。
3. 运行现有 build、Vitest、pytest；记录退出码与失败用例。若存在既有失败，保留最小复现和原因，不伪造绿色基线。
4. 审核 W01 状态转移和错误契约，特别是退出拒绝、结果未知和恢复失败。
5. 出口：基线可复现、数据隔离可证明、缺失依赖有明确记录。

### G1 后端协议检查

1. 先跑注册/登录/定向刷新/退出，确认 schema 与 Cookie 头。
2. 再跑错误 sid/Cookie、CSRF、过期和撤销的负向组合。
3. 使用多个连接验证配额，使用临时文件 SQLite 避免内存数据库连接差异掩盖竞争。
4. 回归业务鉴权、迁移和固定 Refresh 有效期。
5. 出口：没有越权、没有跨会话撤销、并发不突破上限。

### G2 前端认证检查

1. L1 验证匿名不刷新、队列去重、退避、退出和 /me 资料加载。
2. 用可控 Promise 验证每个响应在身份切换前后到达的分支，分别检查 resolve/reject/finally。
3. 验证 http 成功、401、403、Blob/流错误和取消，不只测正常 JSON。
4. 接入真实前后端，Chromium 执行 T01–T04 基础多页冒烟。
5. 出口：真实双页独立身份成立，单元用例无迟到污染。

### G3 业务状态检查

1. JD 保存、路由切换、同账号第二页、换号和整页 reload。
2. SSE、历史、报告、录音授权延迟、STT/TTS 响应延迟时退出或卸载。
3. 检查暂停播放、tracks 停止、URL 撤销、流读取结束和监听注销。
4. 出口：旧内容与资源不进入新身份；取消不显示普通错误。

### G4 简历同步检查

1. L1 测合并、补拉、失败保留、恢复加载与重复订阅清理。
2. 真实双页依次上传、保存版本、删除、设为当前、修改标题。
3. 注入通知失败与 GET 失败，确认写成功仍成功且无自动重传。
4. 检查选择和草稿保留，以及选中简历删除后的新请求阻止。
5. 出口：列表最终与后端一致，通知不影响身份和聊天上下文。

### G5 浏览器和生命周期检查

1. 三个浏览器项目执行全部适用 L3 用例；记录实际版本。
2. 人工执行原生复制、关闭恢复和 BFCache；确认事件是否真实发生。
3. 真机切后台、恢复、录音和播放；记录设备、系统、浏览器与 HTTPS 环境。
4. 在隔离环境进行容量和升级/回滚演练。
5. 出口：T01–T22 均有结果，未覆盖项没有被标成通过。

### G6 最终检查和报告

在最终代码上运行 build、相关 ESLint、Vitest、pytest 与浏览器回归。汇总人工证据、缺陷与未验证范围；只有必测项通过才更新对应任务为通过。实现后的文档反映实际能力，生产发布不由本流程自动触发。

## 5 关键用例的逐步执行

### S01 真实双页隔离

1. 新建一个 context，打开 P1/P2，同源访问应用；通过 UI 分别登录 U_A/U_B。
2. 测试进程捕获登录响应，仅将别名和一致性断言结果写入报告；验证 JWT sid 等于响应 session_id。
3. 两页分别上传带 U_A/U_B 测试标记的简历，检查页面列表和真实 GET 结果无交叉。
4. 等待或在仅测试环境控制 Access 到期，分别触发请求，检查 refresh URL 使用原 sid。
5. P1 退出；检查精确 Path Cookie 被移除，P2 Cookie 仍在，P2 可刷新。
6. 用已保存于测试进程内的 P1 旧 Access 验证 /me 为 401，清理测试变量和 context。

只通过脚本调用刷新接口能证明协议，不能证明客户端自动刷新；步骤 4 至少有一例必须由应用正常请求触发刷新。

### S02 刷新与退出竞争

1. 已登录后用可控 transport 挂起 refresh，发出多个业务请求并点击退出。
2. 断言新业务请求立即被阻止；已挂起业务请求取消；logout 等待已开始的 refresh。
3. 释放 refresh 成功，确认 phase 仍为 loggingOut，无定时器重开，再释放 logout 204。
4. 断言凭证和业务树清理，旧 pending 的 finally 不清除后续新身份的 pending。
5. 分别重跑 refresh 失败、logout 500、logout 超时、logout 401/403 分支。
6. 结果未知时验证重试退出；另测后端已经删除但响应丢失的情况，第二次 logout 204 后正确清理。

使用 Promise 屏障安排先后顺序，不靠随机 sleep 制造竞争。L1 测完整分支，L3 至少复现一次请求延迟和退出结果未知。

### S03 写成功但后续同步失败

1. P1/P2 同账号，P1 保留有效选择和未提交草稿。
2. P2 上传真实成功，记下服务器提交返回时间；令随后本页列表 GET 返回 500。
3. 断言 P2 显示上传成功和独立同步错误，上传 POST 次数恰为一次；P1 仍收到事件并重新加载。
4. 另起用例仅让 postMessage 抛错，断言写 Promise 仍成功，本页列表仍可失效重拉。
5. 令写请求直接返回失败，断言无成功事件、无误清表单。
6. 检查数据库真实条数，恢复 GET 后列表与数据库一致。

写请求超时另列“结果未知”：GET 对账不能仅凭请求取消推断没有写入，也不得自动重传。

### S04 列表请求期间再次失效

1. P1 初始列表已加载，启动 GET1 并挂起。
2. P2 完成写入并发布失效；P1 此时将 dirtyVersion 递增，不并行发第二个 GET。
3. 释放旧 GET1，确认仍 stale，接着发 GET2；GET2 返回最新列表后才解除 stale。
4. 注入重复 eventId，确认不会额外广播或重复无限刷新。
5. 将 GET2 改成 500，确认保留列表且可重试，没有 finally 触发的忙循环。

合并窗口使用假时钟精确验证：首条事件后 200 ms 内多次失效只发一次请求，持续事件不能无限推迟首次请求。

### S05 选中简历被删除

1. P1 选择 R_A1，输入草稿并启动一条可控流；P2 删除 R_A1。
2. P1 列表刷新后选择清空，显示失效提示；草稿和聊天保留，已开始流仍可结束。
3. 尝试发送新消息或结束面试，断言不发送携带失效上下文的请求。
4. 再来一条列表通知，不得自动选 R_A2；用户主动选新简历并新建会话后恢复操作。
5. 另一用例只由 P2 设 R_A2 为当前，断言仍存在的 R_A1 不被替换。

### S06 录音与音频迟到

1. 挂起 getUserMedia，卸载或退出，然后返回 MediaStream，断言 tracks 全部停止且无 recorder/STT 新请求。
2. 正在录音时退出，断言解绑 onstop 后停止录音，不因停止事件提交转写。
3. 挂起 STT、TTS，换号后释放，断言无新输入、Toast、音频 URL 或播放。
4. 同账号同 sid 下主动停止生成仍保留已生成文本，但不会自动合成被取消回答。
5. 真机重复上述能实际操作的流程，检查麦克风占用和播放停止，不只观察组件状态。

### S07 配额与容量

1. 测试配置设小上限，例如 3；账号已有 2 条有效会话，使用独立连接并发发起多次登录。
2. 断言最终有效数不超过 3，成功登录不超过 1；其他响应是 409 或已定义的锁冲突 503，没有 500 和多余 Cookie。
3. 若全部 503，释放锁后顺序登录必须补满剩余名额；满额后稳定返回 409。
4. 将一条会话置为过期，再登录可成功；原其他有效 sid 不变。
5. 浏览器隔离环境增加重复 reload/login 次数，分别观察会话上限和 Cookie 缺失；不假定固定浏览器容量。
6. 单账号上限可能先于 Cookie 配额触发；跨账号容量探测单列，限制运行次数，记录实际配置和停止原因，不将未达到配额当作容量验证通过。

## 6 现有回归与额外断言

| 用例组 | 要求 |
| --- | --- |
| REG 注册 | 201 UserOut、没有 Token 和会话；注册后主动登录 |
| NET 请求 | JSON、204、真实 FormData boundary、Blob/stream 错误解析、取消保留 |
| STREAM | 中文跨块、结构化事件、done/[DONE]、断流与手动停止 |
| USER 用户资料 | login 与订阅同时触发时 /me 仅一次；失败重试不新建 sid；返回 id 不匹配拒绝 |
| RESOURCE 清理 | StrictMode/HMR 后监听、timer、频道和请求注册数量回到预期；重复挂载不累积 |
| RESUME 并发 | 双连接创建版本和设置 active，版本与 active 约束按产品语义成立；失败需修复而非只重拉列表 |
| AUTH 头部 | 认证错误也 no-store；无 Domain；Secure=true 实际通过 HTTPS 验证；HTTP 开发环境单独记录 |
| AUTH 状态 | 403 配置错误不退避循环；logout 拒绝不显示成功；无 sid 不能发 refresh |

## 8 证据与失败处理

每次执行建议填写下表，结果可保存为独立验收记录，避免把计划正文变成日志。

| 字段 | 内容 |
| --- | --- |
| 运行身份 | 日期、Git 版本及未提交改动摘要、任务编号 |
| 环境 | OS、实际浏览器版本、设备、前后端地址、数据库隔离标记 |
| 替换范围 | 哪些服务使用 Mock，哪些请求和数据库真实执行 |
| 用例 | T 编号/额外回归组、操作和预期 |
| 结果 | 通过、失败、阻塞、未执行；命令退出码、实际观测 |
| 证据 | 脱敏日志、截图、请求计数、数据库断言、生命周期事件 |
| 缺陷 | 最小复现、影响范围、修复版本、复测结果 |
| 清理 | 测试进程停止、测试资源处理、无真实数据改动 |

自动化 trace/HAR 可能包含测试认证信息，不能直接公开或提交仓库。仅使用临时测试账号，证据共享前脱敏；取消把完整 Token 或 Cookie 打进断言失败输出的做法。

P0 失败立即停止交付；P1 未完成则列为未验收，不能宣称整个方案通过。既有失败、环境阻塞和本次回归分别统计。修复后先重跑失败用例及关联场景；最终在同一代码版本完成全量检查。

真正的完成条件是：实现任务有对应测试证据，T01–T22 和必要回归均有明确结果，真实多页身份隔离成立，未验证设备或外部服务范围如实列出。当前所有结果仍为待执行。
