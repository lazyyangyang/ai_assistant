# 60 / 80 并发前后端测试（2026-10-30）

## 结论与口径

独立 API + Worker + Redis 的真实 HTTP/SSE 测试：60 并发三批 180/180 成功，80 并发三批 240/240 成功，接收全文、数据库全文与结构化结果均符合固定预期。这里的一致性不是模型业务准确率：全部使用模拟模型，没有调用真实模型。浏览器功能测试与前端并行消费测试另列，未运行 60/80 个真实浏览器页面并发压测，未测该规模下页面帧率、CPU、内存或交互延迟。

## 隔离和配置

两个档位顺序运行，各自新建测试数据库/Redis 实例，API、Worker 为独立进程。模拟输出为 40 个片段，每片段等待 25ms，初始等待 100ms，结构化等待 200ms。Worker 8 槽位，SQLite 每进程 5+10 连接，WAL，busy_timeout=5 秒，队列容量 100。HTTP 压测客户端最多 100 连接，SSE 观察期限保持 25 秒。连接池追踪开启，会增加开销。前端测试和回归在容量计量结束后或两档之间运行；未与容量计量阶段并行。故障检查阶段有回归执行，不作为性能基准。

60 个和 80 个独立账号，每批每账号提交一个任务；每档三批突发并发，非长时间稳态到达负载。未修改业务 .env、业务数据库或系统 Redis。仓库已有数据库 WAL/SHM 文件未清理。脚本已结束并清理其子进程。

首字延迟从提交开始计，含接收/排队等待；完成耗时还包括终态查询验证。非模型单次推理耗时。80 并发的吞吐仅比 60 增加约 3.6%，完成 P95 增加约 31.9%；8 槽位下增加提交并发主要增加等待。不能由此推断真实模型生产容量或相对旧架构提升。

两档均通过断流重连、终态幂等、跨用户拒绝、取消、Worker 强杀后 interrupted、重启后新任务。强杀后的租约回收约 30.69s / 31.75s。API/Worker 日志无错误。

## 前端与回归

- 后端 pytest：41 passed。首次沙箱运行 39 passed、2 个 tmp_path 权限错误，获准沙箱外重跑全部通过。
- 前端 Vitest：12 个文件、45 passed，其中新增 60/80 路 JD observeRun 并行测试，检查中文三字节分块、重复事件去重、独立任务输出隔离、终态一致性。
- 专项复测 3 passed；60 路约 1046ms、80 路约 1028ms。这是 Node 环境、模拟 HTTP/内存 SSE 的消费总耗时，包含观察循环等待和断言，不是浏览器渲染速度或真实网络吞吐。
- pnpm run build：TypeScript 与 Vite 生产构建通过；Vite 构建阶段约 934ms。构建耗时不是页面加载性能。存在既有 __dirname/configLoader 兼容提示。
- Playwright：使用本机 Edge 156.0.4314.50，12 passed，约 1.8 分钟。覆盖认证、多标签恢复/隔离、简历同步、退出失败、401 刷新、JD 内存隔离。测试使用隔离 FastAPI 与模拟模型；已有浏览器用例并非新 JD Worker 流程的完整浏览器验收。
- 首次默认 Chromium 因浏览器可执行文件未安装，12 项均在启动前失败；随后使用已安装 Edge 完整重跑。没有将环境失败计为业务测试通过。
