# CSS/SMIL 混合与统一 SMIL 时间线对照

日期：2026-10-30。仅生成测试构建，未替换产品实现。

## 实验

- A：现有 CSS 跑道/身体/阴影 + SMIL 四肢。
- B：四肢关键帧保持不变；跑道改用 animateTransform(scale)，身体改用 animateTransform(translate)，阴影改用 rx/opacity 的 animate，均由同一个 SVG 时间线管理。
- 两份独立生产构建，同一 Chrome 有界面测试实例，交替 A/B、B/A 顺序，新上下文、禁用 HTTP 缓存，1365×1100，正常 CPU，本地预览。
- 单页和同时 8 页各四轮，每次观察 load 后 2 秒。主对照 16 次测量，比较最后打开的页面。另做单页各三轮、不读取变换矩阵的辅助对照。
- 20 ms 采样路径 getBBox 与跑道/身体 getCTM；首次变化由数值差判断，采样并非实际屏幕逐帧录像。
- B 保留原跑道方向和周期，但阴影缓动、透明度曲线及 DOM 包装不是像素级完全一致。它是验证时间线假设的实验版本，不是已验收的最终实现。

## 结果

| 模式 | 标签页数 | 首次四肢变化延迟中位数 | 四肢落后跑道的采样差值 |
| --- | ---: | ---: | --- |
| A 混合 | 1 | 76.3 ms | -19.7 / 0 / 0 / 0 ms |
| B 全 SMIL | 1 | 76.4 ms | 0 / 0 / 0 / 0 ms |
| A 混合 | 8 | 68.8 ms | 18 / 0 / 0 / 18.7 ms |
| B 全 SMIL | 8 | 72.7 ms | 0 / 14.8 / 16.3 / 13.3 ms |

延迟从首次采样开始计，不是导航或首次绘制时间；约 20 ms 的差异与采样精度相当，不足以证明 B 明显更快。首轮 A 仍有浏览器初始启动离群值（首次腿形变化 1345 ms、FCP 1620 ms），原始结果中保留。

不读取 getCTM 的辅助实验：A 延迟 244.4 / 78.2 / 61.9 ms，B 为 64.3 / 63.3 / 79.9 ms，未稳定复现此前约 600 ms 的四肢延迟。该组同时使用更密集的 20 ms 采样，不能将差异单独归因于 getCTM。

两份构建均无捕获的页面脚本异常；抽查暂停后腿形和跑道缩放数值不变。已查看 B 的首页截图，人物与跑道正常显示。未做 B 的真实 Safari、Firefox、减少动态效果专项验收或性能容量验收。

## 判断

本次没有证明“CSS 跑道比 SMIL 四肢早启动约 600 ms”是稳定可复现的根因，也没有证据表明全 SMIL 显著缩短启动停顿。两者通常在同一次或相邻采样中开始变化。

前次 50 ms 采样得到的首周期等待是真实测量记录，但与本次结果不一致。浏览器冷启动、观察时机及主动读取几何信息对渲染调度的影响仍未排除。因此此前关于“SMIL 首周期初始化问题”的说法应保留为假设，不能当作已确认的浏览器缺陷或最终根因。

统一时间线仍有统一控制的维护价值，但不能据此承诺解决肉眼所见卡顿。要证明视觉错拍，应使用不主动读取 DOM 几何的屏幕录制/渲染追踪，在用户实际浏览器环境复现。
