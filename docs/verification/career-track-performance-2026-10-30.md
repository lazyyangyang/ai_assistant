# 首页跑步动画性能对比（2026-10-30）

## 方法

- 在当前工作区构建两份生产产物：完整首页；通过测试专用 Vite 插件移除 CareerTrack 的 import 与 JSX 的首页。未改动产品源码，无后端或真实模型请求。
- 使用本机无头 Microsoft Edge（Playwright Chromium/CDP），1365 × 1000 视口。
- 冷加载交替各 6 次，每次新建浏览器上下文、禁用缓存，CPU 4 倍降速，网络延迟 100 ms、下载 200,000 字节/秒。测试服务器未开启传输压缩。
- 记录 FCP、LCP、首页标题、动画存在与否、未捕获页面异常，并保存截图。
- 内存测试另开上下文，不降速，动画可见；每组运行 60 秒，每 10 秒强制 GC 后记录 JS 堆、DOM 节点和主线程累计工作时间。
- 重跑：在 frontend 中运行 `node scripts/measure-career-track.mjs`。需要已安装的 Edge、项目依赖及本地服务器/浏览器执行权限。
- 原始数据及截图：`frontend/test-results/career-track-performance/`。脚本结束关闭自己的浏览器和服务器。

## 结果

| 项目 | 有动画 | 无动画 |
| --- | ---: | ---: |
| FCP 中位数 | 2768 ms | 2690 ms |
| LCP 中位数 | 2768 ms | 2690 ms |
| FCP 范围 | 2752–2908 ms | 2680–2700 ms |
| 首页正常呈现 | 6/6 | 6/6 |
| 未捕获页面异常 | 0 | 0 |
| 页面 DOM 元素数 | 121 | 71 |
| GC 后 JS 堆，开始 | 2,505,532 字节 | 2,298,068 字节 |
| GC 后 JS 堆，60 秒 | 2,529,240 字节 | 2,298,068 字节 |
| CDP DOM 节点数（包含其他节点类型） | 全程 162 | 全程 102 |

首屏直接引用 JS/CSS 增加 5,476 字节，离线 gzip 比较增加约 1.7 KB；不增加动画图片或视频请求。限速测试中 FCP 中位数增加 78 ms（约 2.9%）。小样本和本机环境存在噪声，不代表所有设备或线上延迟。

有动画时 JS 堆在 0–60 秒增长约 23 KiB，最后两次相同，未出现持续增长趋势；稳定堆相比无动画约多 0.22 MiB。这只是 JS 堆，不包含完整浏览器进程、GPU 或渲染器原生内存，不能据此声称总内存只增加这些。

动画运行 60 秒，主线程 TaskDuration 增量约 8.10 秒（测量时间的约 13.5%），其中 LayoutDuration 约 0.40 秒、RecalcStyleDuration 约 1.20 秒。无动画页面对应增量约 0.055 秒，基本空闲。这不是整机 CPU 百分比，也不是帧率测量，但说明持续动画确实有渲染成本。

## 判断与限制

- 本次未复现持续白屏，截图可见首页文字、功能卡片和跑步场景；12 次加载均有正常标题，未捕获页面脚本异常。FCP 前仍有 SPA 初始化等待，不能称为零白屏时间。
- CareerTrack 仅暂停按钮使用 React state，没有逐帧 setState、JS 定时器、外部动画资源。CSS 的 SVG `d` 路径插值会持续触发样式计算/布局/绘制，不能视为完全无成本的合成动画。
- 本次未发现一分钟范围内的明显 JS 堆泄漏；未测试长时间运行、真实手机、GPU 内存、浏览器扩展、Safari/Firefox 或线上资源失败。
- 建议后续优先增加离屏/后台暂停，并比较关节 transform 动画与当前路径插值的开销。现有暂停按钮和 reduced-motion 样式可减少运动，但本次未做独立性能对比。
- 本任务只增加测试脚本和报告，没有改变产品动画或业务代码。
